JSRegex: measured behavior and counted work

This report checks match results, varies both input dimensions, and compares identical matching tasks with two V8 engines. All plots are generated from the raw samples beside this file.

The product bound comes from the algorithm and its proof. The plots illustrate finite runs. Independent operation counts below check the implementation of the bounded loops; elapsed-time curves alone do not establish an asymptotic bound.

What each panel computes

  • A–B: product scaling. Start with a?, wrap it in (…)+? d times. On a repeated n times, the selected end at x is min(x + 1, n), with d nested captures. The original tree has m = 2 + 2d occurrences and the text has N = n + 1 positions. Both m and N vary independently. Only construction of our all-start word index is timed; every root endpoint is checked afterwards. B divides time by mN; JIT, allocation, garbage collection and fixed costs can make the ratio fluctuate.
  • C: all global matches. .*a|b on n copies of b returns n one-character intervals. We time our index construction plus scan, or V8's complete matchAll traversal and collection of the same intervals. All returned intervals are checked. Repeated searches can revisit long suffixes even when one search uses a linear engine.
  • D: one unanchored search. (((a?)+?)+?)+?b on n copies of a must fail. We time our index construction plus first-match scan, or one V8 exec. The experimental linear engine handles this depth on the recorded version; the default backtracking engine can reach the call limit. The index prepares all starts even though this client asks for only one result.

Triangles mark a call stopped at its time limit, not a completed measurement. The data record whether it stopped in warmup or measurement. Larger inputs for that engine and experiment are then marked not-run. A rejected pattern is unsupported, never a zero time. These deliberately demanding families are not a survey of typical production throughput.

Executed work, independently counted

All 63 instances passed. Node precise coverage counts actual selectCell calls; instrumented predecessor lists count actual pops and edge inspections. For every case the assertions require selections = mN, pops ≤ 2mN, and edge scans ≤ 4mN. Every endpoint and ordered sparse capture result is checked. A query emitting k captures visits no record for k = 0, and at most 2k − 1 records otherwise. This instrumentation is outside the timing runs.

Measurement boundary and environment

Pattern source/tree construction, our tree preparation, the native RegExp constructor, input construction, process startup and result validation are outside the clock. V8 may lazily compile or tier its matcher during a call; the same number of warmups and repetitions is used for each engine. Each sample calls gc() before starting the clock; allocations and collection during matching are included. Processes run serially. Inherited NODE_OPTIONS are removed. Enabling the experimental engine does not enable fallback for the default engine.

A VM time limit surrounds each prepared call, with both timestamps inside it. If setup or the worker itself fails to return, the driver fails rather than recording that as a matching timeout.
